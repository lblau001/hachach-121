# v16 — what the prototype consumes

Everything the prototype needs is in `prototype/`. Three files, no build step,
no bundler, nothing to extract from an artboard.

```
explorations/v16/prototype/
  hachach.css      one stylesheet: tokens in :root, then the components
  manifest.json    id -> asset path, generated from data.js
  components.html  every component rendered from hachach.css alone
```

## How to consume it

1. **Copy `hachach.css` into `styles/`** and load it before `overrides.css`.
   It declares only `:root` and component classes — it does not style any
   existing selector, so it cannot fight the current stylesheets while the
   port is in progress.

2. **Use the tokens, not the values.** Every number and colour in the design is
   a custom property. If a screen needs a colour that is not a token, that is a
   design question, not a CSS one.

3. **Use the components as they are.** Each class in `hachach.css` carries the
   markup it expects in a comment directly above it, and `components.html`
   renders all of them from the stylesheet alone — open it in a browser and
   what you see is what the classes do with no help from anywhere.

4. **Read assets through `manifest.json`.** Never hardcode a portrait path.

   ```js
   const M = await fetch('assets/manifest.json').then(r => r.json());
   const p = M.politicians[pol.id];
   img.src = px >= 150 ? p['400'] : p['128'];      // or the badge, below
   ```

   `manifest.json` is generated by `tools/make_manifest.py` from `data.js` and
   the contents of `assets/mk/`. It asserts every file it names exists, so it
   cannot drift. Regenerate it whenever art is added.

## The four things that are easy to get wrong

**Portraits are TOP-anchored.** Every export puts the crown 2.4% into the file.
`.mf-b__port` sets `top: var(--mk-port-top)` so every crown lands on the same
line on every card. A figure that runs long clips at the BOTTOM. Anchoring the
bottom instead is what cut the top off Deri's head.

**Fifteen of the twenty-one politicians have no art.** `manifest.json` lists
them in `politicians_without_art`. Render the initials badge — first letter of
each part of the shipped name, set at 37.7% of the box. Never substitute
another politician's portrait: that attaches a real person's likeness to a vote
that is not theirs.

**Count the pile from the RENDERED sample.** `app.js:373` deals
`Math.min(5, issue.politicians.length)`. The pile shows `dealt - index - 1`
backs. Drawing `issue.politicians.length` promises a card that never arrives.

**A chip's gap is not the gap you see.** `.v-a` paints `--ring-chip` (4.6px)
*outside* its own box, so two neighbours spend 9.2px of any gap on their own
keylines before any daylight appears. That is why `--gap-chip` is
`calc(--gap-visible + 2 * --ring-chip)` rather than a typed number, and why
`--ring-chip: 0` is the right setting for a row of unringed buttons. And put
the gap on the element **whose children are the buttons** — wrap the three in
anything and a gap on the wrapper spaces a one-child row, silently, while
looking like it worked. Both halves of that shipped broken once.

## Two rules the stylesheet enforces and the prototype must not break

- **Colour codes correctness, never vote direction.** The tokens are
  `--verdict-correct` and `--verdict-surprise`. There is no token for בעד, נגד
  or נמנע and there must not be one.
- **The three vote options are always three and always identical.** `.v-a` is
  one class used three times. Hiding נמנע in a round where nobody abstained
  tells the player the answer before they guess.

## Assets

Referenced by **path**, never embedded. The paths in `manifest.json` are
relative to the app's `index.html` (`assets/mk/...`), which is where they
already live — nothing needs moving.

The `.dc.html` artboards on the published canvas *do* embed their images, because
the canvas is a single self-contained page. That is a property of the canvas
format, not of this bundle. The prototype should read `prototype/`, not the
artboards.
